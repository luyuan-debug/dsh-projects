# 升级与回退

适用于升级到 **DSH Projects v0.3.0-rc.1**。安装包名为 `dsh-project-threads-wave1-spike`，界面入口为 **Projects**。包名与 `project_threads_*` 存储命名空间用于识别既有安装和数据，请勿自行改名。

## 从 v0.1.0-rc.1 升级

本版本使用 **Projects Store schema 5、记忆 schema 2**。`v0.1.0-rc.1` 使用的旧 Store schema 4 需要迁移；插件默认拒绝静默升级。**安装新版并不自动批准修改既有数据。**

迁移适配于已验证 DSH 构建的本地 JSON 存储后端。其他后端、不同宿主构建或来历不明的快照需要另行核对，不能直接套用。

### 1. 停止并备份

1. 暂停相关项目，停止所有 Thread，正常退出使用该 Profile 的 DSH 实例。确认没有另一个实例正在写入同一份数据。
2. 记录旧插件版本、DSH 构建、Profile 名称，以及 `DSH_HOME`、`XDG_DATA_HOME` 和原数据路径。
3. 备份该 Profile 的插件数据目录及配套 `project_threads_*` 存储，保留一致快照、旧安装包和校验文件。
4. 如需在回退后保留新增记忆，另行导出易读副本。不要把账号配置、凭据或完整聊天资料放入公开附件。

插件文件目录由 `DSH_HOME`、Profile 与 `XDG_DATA_HOME` 派生，位于 `dsh-project-threads/<身份哈希>`；元数据由对应 DSH 存储服务管理。不要只备份其中一份就视为完整快照。

建议先用独立 Profile 和备份副本演练。复制数据前确保路径、身份和权限正确，不让两个实例并写，也不要让试用实例执行原项目任务。

### 2. 明确批准这一次迁移

确认备份可用后，安装新包。在**明确选择且已停止其他写入者的 Profile** 启动插件 Host 时，显式设置：

```sh
DSH_PROJECT_THREADS_LEGACY_MIGRATION_APPROVED=1
```

这是由插件 Host 读取的启动环境变量，单独在终端输入这一行、或只给安装命令设置它，不会使已运行的桌面进程获得授权。请在该 Profile 的实际启动环境中配置，完成迁移后移除；不要设为全局默认值。不要直接启动其他 Profile 来代替目标 Profile，也不要手改 Store 的版本号绕过检查。

升级器在插件受管目录的 `migration-backups` 保存原字节、哈希和版本信息，检查存储身份及并发写入后再升级。这个自动备份是补充，不能替代升级前的完整配套快照。

若提示 `MIGRATION_COORDINATION_REQUIRED`，应先核对备份、目标 Profile 和启动环境；若提示存储变化或锁冲突，停止其他实例后重新核查，不能强行覆盖。

### 3. 检查数据

启用后先核对项目、Thread、Memory、Library、工作目录关联和权限。当前记忆、候选及历史应分别可见；先查看来源和版本，再恢复任务执行。

`Hindsight` 默认关闭。旧本地记忆不需要上传到 `Hindsight`，也不会因升级自动绑定或写入远端库。需要增强时，按 [`Hindsight` 设置](HINDSIGHT.md) 单独配置。

## 回退

**旧安装包不能直接读取 schema 5。** 回退需要旧安装包和升级前同一路径、同一 Profile 的配套数据快照：

1. 导出需要保留的新增记忆或资料，停止任务并正常退出对应 DSH 实例。
2. 恢复旧安装包，再恢复升级前的完整配套数据快照。不要只降版本号，或将新旧 Store 混用。
3. 核对项目与授权后再恢复执行。插件不会自动迁移工作区绝对路径，更换目录须重新确认关联和权限。

同一路径不能由两个版本同时写入。插件回退只恢复本地状态，不会撤销已经发送给 `Hindsight` 的内容；远端操作和资料需要按原服务记录单独核对。

## 停用与卸载

停用后 Projects 入口关闭，重新启用可恢复原有项目。卸载不等于删除数据；需要清理项目时，先在 Projects 内确认删除。DSH 会话历史归档保留，用户原文件、仓库和 Worktree 不删除。

断开 `Hindsight` 或删除 Project 默认保留整个远端 bank。外部库由用户管理；可追踪的插件写入文档也需要再次确认后才能请求远端删除。
