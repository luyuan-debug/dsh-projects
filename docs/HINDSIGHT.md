# 连接已有 Hindsight

本说明适用于 **DSH Projects v0.3.0-rc.1**、DSH `0.2.1-rc.2` 与 Hindsight `1.1.0` 接口。插件使用已有服务，不自动部署数据库、下载向量模型或更改服务模型配置。

## 先用 Standard

在 `Project Settings > Memory` 管理本地记忆即可。默认 Hindsight 关闭，不探测服务、不下载依赖，也不为本地检索发送 Hindsight HTTP 请求。

项目概要、当前约定、候选、历史、来源、Library 和 Used This Turn 沿用原入口。开启增强不需要将这些本地数据迁出或整批上传。

## 核对服务和数据出口

先查看实际服务版本、地址、认证方式与模型路由。端点、目标库、Recall 和 Retain 分别验证，不用一次健康响应替代全部测试。

服务地址须从你实际部署的设置中核对，例如 loopback 服务可使用 `http://127.0.0.1:8888`。该地址只是示例，不代表已发现或启动任何服务。若配置使用云端 embedding、重排或远程模型，就不能选择“已核对仅本地且无计费”。本版本的连接与上下文测试使用合成 HTTP 服务和脚本模型；真实 Hindsight Recall / Retain 及真实模型效果尚未验证，详见 [验证范围](RELEASE.md)。

正常启动可能进行 embedding 维度探测或执行已有队列；新建库可能应用默认模板并触发后台模型。恢复服务、新建库和真实读写的授权应分别确认；插件不会替你恢复或升级服务。

## 保存项目连接

1. 打开项目设置中的 **记忆 → 高级记忆（可选）**。
2. 填写服务地址，只使用 HTTP(S) origin，不含用户名、密码、路径、查询参数或片段。本机 loopback 可使用 HTTP；非本机服务需 HTTPS 与明确数据出口确认，不关闭证书验证。
3. 如需认证，填写 **凭据环境变量名**，例如 `HINDSIGHT_API_KEY`。这里只填名称，不填密钥值；变量须由 DSH Host 的既有安全启动环境提供。客户端不直接持有 token 或连接 Hindsight。
4. 按实际核查选择路由授权并确认数据出口。该选项记录用户声明，不会把服务自动认证为“纯本地”。路线或费用不清楚时保留“未知”。
5. 保存设置。版本冲突时保留草稿，先核对其他窗口的修改，再决定如何保存。

## 绑定一个明确的 bank

**已有库**：输入准确 bank ID，确认该库整体属于当前 Project，保存后再检查。默认只读，不修改原库名称、profile、指令、模型或向量。同一服务上的一个 bank 默认只绑定一个 Project；两项目关联同一仓库，也不能据此共用。

**新建专属库**：先保存服务、路由和数据出口授权，再点击“新建项目专属库”。ID 与所有权由 Host 生成和记录。若派生 ID 已存在，插件不会借创建操作改写它，应由用户确认后显式绑定。新库会继承服务默认模板，可能触发模型及费用；这不是无模型的健康检查。

没有目标库访问权限，只阻塞此连接。不要扫描所有 bank、关闭认证或把用户旧库当测试库。缺少 Project 标识的历史也需要整库范围确认，并始终标为 `external-history`。

## 检查与只读召回

点击“检查 Hindsight 连接”只读取健康、版本与已选库元数据；插件不会因此请求 LLM、创建库或写入内容。界面分别显示服务、库、Recall、Retain 和路由状态。服务自身的后台任务仍由其配置决定。

每次检查独立显示本次进度和结果，开始检查时清除旧成功结论。服务不可达或健康异常时，不把库显示为已检查；服务正常但库返回 404、401 等错误时，明确区分服务可达和库不可用。旧检查、旧端点或旧 bank 的迟到结果不会覆盖新状态。历史成功时间单独显示，不能当作当前检查成功。

准备好后，显式开启 Hindsight Enhanced 和历史召回。保持写回关闭。测试框会显示将发送的问题及已保存的端点、bank；确认资料和费用范围后再发送有界问题。

自动召回只服务真实的新任务、授权派工和续聊，不把工具续步、报告回流或已注入记忆当成新任务反复查询。同一回合的去重、权限变更和绑定版本由 Host 控制；改 bank 或端点后旧结果不能接到新绑定上。

默认预算如下，单位为 UTF-8 字节而非精确 token：

| 项目 | 默认值 |
| --- | ---: |
| 自动召回等待 | 2,000 毫秒 |
| 历史上下文 | 6,000 字节 |
| 最多历史条目 | 6 |
| 单条历史 | 2,000 字节 |
| 服务响应 | 262,144 字节 |
| 查询问题 | 4,000 字节 |

先保留本地当前约束，再给历史使用剩余 Packet 预算。完整条目放不下时省略并说明原因，不截掉否定句后伪装成完整结论。超时或服务失败时降级为本地记忆；迟到结果不会补进已启动的旧回合。

## 看懂 Used This Turn

这里将本地记忆的“索引预览（非全文）”与“已提供全文”分开展示，并列出本地来源资料和 Hindsight 历史引用。索引短说明采用首个非空字面行的前 100 个 Unicode 字符，保留符号并标记多行或截断；应读取逻辑文件后再采用具体结论。外部条目保留可用的 bank、document/fact ID、日期和来源；缺失字段显示未知，不补造审批、commit 或测试依据。

持久记录不另存 Hindsight 历史全文，只保留引用与省略/降级信息。模型当回合已经收到的正文仍可能留在 DSH 正常会话历史中。Used This Turn 只记录已组装到本轮上下文的内容，不证明请求发送成功或模型理解，也不代表历史内容得到当前用户批准。

自动召回去重记录有容量上限：最多 200 个 Session，每个当前回合 100 个消息 ID；达到上限会说明原因并降级本地。写回收据最多 200 条，满后需先审查，当前没有批量清理界面。不要把小语料验证推导为无限规模支持。

## 需要写回时再开启

先确认共享完成 Thread 的任务经验，再单独开启写回。发送对象是启用后符合条件的、已持久化的终态报告，不是全部聊天或工具结果。私有 Thread、私有 Library 和敏感内容受到额外限制；私有记忆即使只以索引预览出现，也会阻止相关报告外发。项目共享 bank 不能替代私密资料授权。

报告保留任务、失败尝试、结果引用及分支身份，不把报告中的声称升级为工具实测。不额外启动 DSH 总结模型；服务端自身仍可能使用 embedding、LLM 或后续归并并产生费用。

写回记录区分排队、已接收、已确认、失败和结果未知。`accepted` 不等于 `completed`，也不等于已经能召回。遇到未知结果，先检查原 operation/document；不要换随机 ID 盲发。当前“检查此写回状态”用于核对原写回，不承诺重试或 exactly-once。

## 关闭、断开与忘记

关闭增强或写回会停止新发送；暂停/归档、撤销或停用也会取消或失效化本地等待。已到服务端的操作可能继续。

断开本项目连接不删除远端库。删除 Project 也默认保留 bank。仅对可追踪、本插件写入且属于当前专属绑定的文档，才能再次确认后请求远端删除。外部库只做本项目本地抑制，远端由用户管理。

本地忘记不会清除已有聊天或 Library 原文。由于同义副本和服务端派生观察未必可完整过滤，当前实现会暂停增强以防已忘记材料再注入，Standard 仍可用。
