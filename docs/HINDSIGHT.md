# 连接 `Hindsight`

项目记忆默认使用本地 Standard，不需要外部服务。`Hindsight` 是可选的历史记忆服务，需要另行部署；插件只负责连接，不安装服务或管理模型。

本版本适配 `Hindsight 1.1.0`，目前只完成模拟服务测试，真实记忆库读写和模型效果尚未测试。建议先使用专用测试库。

## 配置连接

打开 **项目设置 → 记忆 → 高级记忆（可选）**：

1. 填写服务地址，例如 `http://127.0.0.1:8888`。这里只接受服务 origin，不含路径、查询参数或账号密码；非本机连接需要 HTTPS。
2. 如需认证，只填写 Host 能读取的凭据环境变量名，不填写密钥正文。
3. 填写已有 bank ID，确认整个库属于当前项目。一个项目使用一个库，已有库默认只读。
4. 选择服务的数据出口和费用路线。尚不清楚时保留“未知”。
5. 保存设置，点击连接检查。服务健康与记忆库访问会分别显示结果。
6. 确认配置后再启用增强。写回任务报告需要另外开启共享和写回选项。

本机服务仍可能调用云端 embedding、重排或语言模型，产生费用和数据外发。不能仅凭 `127.0.0.1` 判断模型也在本机运行。

新建记忆库可能继承服务模板并触发模型调用，需先确认路线和费用。插件不会修改已有库的模型或配置。

## 读取历史

启用增强后，项目会在允许的范围内补充相关历史。当前项目约定优先，历史内容只作参考。

服务故障、超时或达到容量上限时，项目继续使用本地记忆。关闭增强也不会删除本地文件、历史或资料索引。

使用记录会显示历史来源、状态和省略原因，不另存完整历史正文。已发送的内容仍可能留在 DSH 会话中。

## 写回任务报告

写回默认关闭。开启后，只处理符合共享条件的已完成任务报告，不补传全部旧会话，也不批量上传源码或项目记忆。

私有 Thread、Library 和记忆预览受共享限制。连接同一 bank 不会自动改变这些权限。

写回“已接收”不等于服务处理完成，也不保证之后能召回。结果未知时，先检查原写回记录，不要重复提交。

## 连接状态

每次检查都会更新当前结果：

| 状态 | 含义 |
| --- | --- |
| 检查中 | 正在读取健康信息或目标库元数据 |
| 服务失败、库未检查 | 健康请求失败或服务返回异常 |
| 服务可达、库失败 | 服务正常，但目标库不存在或无访问权限 |
| 服务可达、库可访问 | 本次健康和库访问检查成功 |

历史成功时间只表示上一次结果。连接检查不调用模型，也不验证历史写入或召回效果。

## 忘记与断开

忘记会先在本地抑制对应内容，并暂停增强，避免外部历史重新带回旧内容。它不会删除原文件、聊天或所有远端副本。

断开连接或删除项目不会删除整个远端 bank。对能追踪到的插件写入文档，可在确认后请求删除；其他外部数据需在原服务管理。

停用、解绑或撤权可以停止新请求，已经被远端接收的操作可能继续。切换服务或 bank 不会将旧待发项转送到新绑定。

## 容量

默认查询等待 2 秒，历史上下文最多 6,000 UTF-8 字节，最多 6 条结果。高级设置可调整等待和上下文预算。

自动召回记录最多覆盖 200 个 Session，每个当前回合 100 个消息 ID；达到上限后改用本地记忆。写回收据上限为 200 条，目前没有批量清理界面。

完整范围见 [已知限制](KNOWN_LIMITATIONS.md)。
